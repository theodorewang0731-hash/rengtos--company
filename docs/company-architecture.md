# RegentOS 公司分层治理结构

本文档是 README 的组织扩展版，重点说明 RegentOS 在现代公司场景中的层级关系、权限边界、升级路径与组织映射。

## 1. 三层同构治理

RegentOS 把治理能力拆成三层：

- 个人层：员工终端、本地工作流、个人 Agent 工作台。
- 部门层：产品、工程、市场销售、运营客服、财务 / 法务 / HR / 行政等职能部门。
- 公司层：跨部门协调、重大审批、重大修复、战略级决策与治理。

除锦衣卫外，每层都包含四类治理单元：

- 通政司：任务 intake 与案件化
- 内阁：票拟与执行协调
- 司礼监：审批、封驳与修复令审定
- 台谏院：常规监督与稽察

## 2. 锦衣卫的垂直直属链

锦衣卫是唯一不采用层内横向汇报结构的治理单位。它遵循：

```text
个人锦衣卫 → 部门锦衣卫 → 公司锦衣卫 → 老板 / 董事会
```

设计目的有三点：

1. 保证重大风险不会被层内利益关系压住。
2. 让重大异常、绕流程行为和高等级事故有独立调查线。
3. 让老板 / 董事会看到的是经过筛选和分级后的最高价值问题，而不是噪音。

## 3. 管理层查看边界

RegentOS 不允许“职位高就可以全看”。

### 员工

- 只能看本人任务与本人问题档案
- 无权查看同部门其他员工的个人问题

### 部门管理层

- 只能看自己负责业务的问题
- 可以看本部门授权范围内的 `L2 / L3` 问题
- 无权查看其他部门问题

### 公司管理层

- 只能看自己分管业务线的问题
- 只能看授权范围内的部门档案
- 无权做全域开放查询

### 锦衣卫

- 具有高于普通管理层的调查可见性
- 该可见性仅服务于监察、诊断、归档和升级
- 不能将全域访问变成开放式浏览

### 老板 / 董事会

- 拥有全公司、全层级、全等级问题查看权
- 可穿透查看任意部门、任意员工、任意案件
- 可查看问题历史、升级路径、修复结果与监督记录

## 4. 问题分级与升级逻辑

### L1

- 影响局限于个人层
- 可在本层闭环
- 部门锦衣卫可抽查

### L2

- 影响部门内某个小组或局部业务
- 需要部门资源介入
- 由部门层进入修复流程

### L3

- 影响跨小组、跨系统或核心业务
- 需要公司层协调或批准
- 需要老板授权后才能进入重大修复流程

### L4

- 涉及多个部门、重大风险、重大合规或品牌问题
- 由公司锦衣卫直接报告老板 / 董事会
- 可触发修复令、冻结令、重跑令或终止令

## 5. 现代公司部门映射建议

制度代号保留明制逻辑，现实部门使用现代命名：

- 公司通政司：PMO / Product Ops Intake
- 公司内阁：Strategy & Delivery Office
- 公司司礼监：Governance Board
- 公司台谏院：Audit, Quality & Oversight Office
- 公司锦衣卫：CEO / Board Special Inspection Office

部门层则在各业务条线内部复用通政司、内阁、司礼监、台谏院与部门锦衣卫接口。

## 6. 组织图

```text
董事会 / 老板
│
├── 公司级治理层
│   ├── 公司通政司
│   ├── 公司内阁
│   ├── 公司司礼监
│   ├── 公司台谏院
│   └── 公司锦衣卫（直属董事会 / 老板）
│
├── 产品部
├── 工程部
├── 市场与销售部
├── 运营与客服部
└── 财务 / 法务 / HR / 行政
```

个人层部署在员工终端：

```text
员工个人终端
├── 个人通政司
├── 个人内阁
├── 个人司礼监
├── 个人台谏院
└── 个人锦衣卫（直属部门锦衣卫）
```
